# ADR-0001. Способ развёртывания TimeCapsule

- Статус: принято
- Дата: 2026-10-04

## Контекст

Для приложения TimeCapsule нужно было выбрать способ обновления кода на сервере AWS EC2. Код приложения хранится в репозитории GitHub, а изменения в коде сначала вносятся на локальном компьютере.

Важно, чтобы выбранный способ позволял удобно обновлять приложение и при необходимости возвращаться к предыдущей рабочей версии.

## Решение

Для проекта выбран ручной деплой через Git.

Сначала изменения отправляются с локального компьютера в репозиторий GitHub. После этого выполняется подключение к серверу EC2 по SSH, и сервер получает новую версию приложения из репозитория.

Такой способ позволяет использовать историю Git и при необходимости отменить неудачное изменение. Это было проверено при выполнении задания с ошибочным деплоем и последующим откатом.

## Рассмотренные альтернативы

### 1. Копирование через `scp`

Файлы приложения можно передавать с локального компьютера прямо на сервер с помощью `scp`. Способ достаточно простой, но при обновлении нескольких файлов можно пропустить часть изменений. Также такой вариант менее удобен для контроля версий.

### 2. Ручной `git pull`

Код приложения хранится в GitHub, а сервер получает из репозитория актуальную версию. При этом сохраняется история изменений, и при необходимости можно выполнить откат к рабочей версии.

Этот способ был выбран для данной работы.

### 3. Скрипт `deploy.sh`

Процесс обновления приложения можно автоматизировать с помощью скрипта, который последовательно выполняет необходимые действия. Это сокращает количество ручной работы и снижает вероятность пропустить какой-либо шаг.

Для данной работы этот вариант не использовался, так как был выбран ручной способ деплоя.

## Последствия

**Плюсы:**
- все изменения сохраняются в GitHub и можно посмотреть историю версий;
- при ошибке можно отменить неудачное изменение и вернуть рабочую версию;
- не нужно каждый раз копировать файлы приложения на сервер вручную.

**Минусы:**
- для обновления приложения нужно вручную подключаться к серверу;
- необходимые действия при деплое выполняются вручную, поэтому можно пропустить какой-либо шаг;
- процесс развёртывания не автоматизирован.
